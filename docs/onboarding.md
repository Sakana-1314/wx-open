# 接入操作手册（onboarding）

面向**第一次把平台接到真实微信开放平台**的人。每一步都写成可勾选的形式：

> **在哪里点 → 填什么值 → 期望看到什么 → 出问题看哪一节**

配套文档：业务与命令速查见 `README.md`；故障处置见 `docs/runbook.md`；官方依据都摘自 `docs/reference/wx-open-platform-api.md` 与 `docs/wx-docs/*.md`。

约定：

- 「**你**」= 服务商侧操作人（本项目维护者）；「**商家**」= 小程序管理员（要扫码授权的人）。
- 路径写法 `A → B → C` 表示在开放平台后台逐级点击。
- 凡是**微信没有 API、只能人工在后台点**的动作，都用 【人工】 标出；凡本平台**不提供**的能力，都用 【本平台不做】 标出。

## 第 0 步：先准备这些材料

在做任何配置之前，把下面 7 项凑齐，否则后面一定要返工。

| # | 材料 | 说明 | 谁准备 |
|---|---|---|---|
| 0.1 | 微信开放平台账号（**已完成开发者资质认证**） | 官方原文：第三方平台账号审核免费，但**开放平台账号认证需缴 300 元** | 你 |
| 0.2 | 对外可用的**官方网站** | 创建第三方平台时必填，且网站提供的服务描述要与平台名称/简介/图标相关 | 你 |
| 0.3 | **平台图标** | 提交审核前必上传，必须为你方所有 | 你 |
| 0.4 | 一台**公网可达**的服务器（能跑本平台后端） | 回调必须能被微信访问；`https` 对应 443 端口，`http` 对应 80 端口 | 你 |
| 0.5 | 该服务器的**公网出口 IP**（NAT 出口按真实出口 IP） | 要写进 IP 白名单，多个出口全部要记下来 | 你 |
| 0.6 | 平台**前端域名**（例：`wx.example.com`） | 要写进「授权发起页域名」，且必须与授权回调地址同域 | 你 |
| 0.7 | 一台**测试小程序**（普通小程序，已完善头像/昵称/简介/类目） | 未全网发布前只能用它联调 | 你或商家 |

依据：`docs/wx-docs/extra5_how_to_be_11f.md`。

**检查点 0**：0.1-0.7 全部就绪，且 0.5 的出口 IP 已实测确认（在服务器上执行 `curl -s https://ifconfig.me` 与云厂商控制台的出口 IP 一致）。

## 第 1 步：创建「平台型」第三方平台

| 步骤 | 在哪里点 | 填什么值 | 期望看到什么 |
|---|---|---|---|
| 1.1 | open.weixin.qq.com → 管理中心 → 第三方平台 → 创建 | 名称、简介、图标、官网 | 提交后进入审核 |
| 1.2 | 创建时的**账号类型选择** | **必须选「平台型第三方平台账号」** | 创建后详情页能看到 **AppID 与 AppSecret** |
| 1.3 | 详情页 | 记录 AppID / AppSecret | 后面要填进 `server/.env` |
| 1.4 | 详情页 | 若忘记 AppSecret，点「重置」 | 重置后**旧 AppSecret 立即失效**，须同步更新 `WX_COMPONENT_APPSECRET` 并重启后端 |

**为什么必须选「平台型」**：只有平台型才有 secret 与代调用能力。「定制化型」只有一个 APPID、**没有 secret，不能调任何官方接口**，完全不适合本平台（`docs/wx-docs/extra5_how_to_be_11f.md`）。

**数量上限**：一个已完成开发者资质认证的开放平台账号，**最多创建 5 个平台型第三方平台账号**。多套环境请提前规划好哪个账号对应哪套环境。

**检查点 1**：AppID / AppSecret 已记录到安全的地方（密码管理器），不要把 AppSecret 写进 git。

> 出问题看：第 10.6 节（AppSecret 重置后接口全部 `40125`）。

## 第 2 步：先在本机把平台跑起来（拿回调 URL）

回调 URL 不是手写的，是平台根据 `PUBLIC_BASE_URL` 推导出来的。

```bash
cd /workspace/微信开放平台
make db-init
cp server/.env.example server/.env
# 编辑 server/.env，至少填两项：
#   JWT_SECRET=<32 位以上随机串>
#   ADMIN_PASSWORD=<你的登录密码>
# 若是先做无凭据联调，可先加：MOCK_WX=1
make dev-backend
```

启动日志里会直接打印两行需要填进后台的地址：

```
请在开放平台后台填写：授权事件接收 URL = https://wx.example.com/callback/component，消息与事件接收 URL = https://wx.example.com/callback/message/$APPID$
```

也可以登录平台前端（<http://127.0.0.1:5174>，`admin` + `ADMIN_PASSWORD`）在**概览 → 接入配置**卡片里直接复制这两个 URL（接口 `GET /platform/status` 的 `authorizationEventUrl` / `messageEventUrl`）。

| 项 | 期望看到什么 |
|---|---|
| 后端启动 | 打印「微信第三方平台管理平台启动，监听 :8091」 |
| 未配微信凭据时的日志 | 打印「警告：第三方平台凭据未配置完整，服务可启动但无法调用微信接口（请见 README 的接入指引）」 |
| `curl -i http://127.0.0.1:8091/healthz` | `200` + `{"status":"ok"}` |
| 概览页 | 出现「第三方平台凭据未配置」告警（配置完成后会消失） |

**检查点 2**：`PUBLIC_BASE_URL` 已改成**公网可访问的域名**（生产必须 https），且 `curl -i {PUBLIC_BASE_URL}/healthz` 从外网能返回 200。

> 出问题看：第 10.1 节（授权链接打不开）。本地无凭据联调请改用 `MOCK_WX=1 make dev-backend`，见 `README.md` 4.4 节。

## 第 3 步：生成两个密钥/令牌并写进 .env

先生成随机值，再一次性填进后台与 `server/.env`，避免两边不一致。

```bash
# 消息加解密 Key：必须 43 个字符，只含 a-z A-Z 0-9（微信后台限制）
LC_ALL=C tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 43; echo
# 消息校验 Token：任意随机串即可
head -c 24 /dev/urandom | base64 | tr -d '\n=+/'; echo
# refresh_token 落库加密密钥（base64 编码的 32 字节）
head -c 32 /dev/urandom | base64
```

**注意**：第一条命令产出的是**恰好 43 个字母数字字符**——含 `+` `/` `=` 会被微信侧拒绝，本平台启动时也会校验并报错「`WX_COMPONENT_ENCODING_AES_KEY` 必须是 43 个字符」。不要用 `base64` 再去掉符号的做法（长度会不足 43）。

**检查点 3**：`server/.env` 里 `WX_COMPONENT_ENCODING_AES_KEY` 长度 = 43；`SECRET_ENC_KEY` 解码后 = 32 字节（不填会由 `JWT_SECRET` 派生并在日志中提示，生产建议显式配置）。

## 第 4 步：填写「开发配置 → 开发资料」

路径：**微信开放平台 → 管理中心 → 第三方平台 → 详情 → 开发配置 → 开发资料**。

### 4.1 后台字段 ↔ 环境变量对照表（核心表）

| # | 后台字段 | 填什么值 | 对应 `server/.env` 变量 | 填错的后果 |
|---|---|---|---|---|
| 1 | **授权事件接收 URL** | `{PUBLIC_BASE_URL}/callback/component` | 由 `PUBLIC_BASE_URL` 间接决定 | 收不到 `component_verify_ticket`，令牌全链路不可用 |
| 2 | **消息与事件接收 URL** | `{PUBLIC_BASE_URL}/callback/message/$APPID$` | 由 `PUBLIC_BASE_URL` 间接决定 | **必须原样带 `$APPID$`**；漏掉占位符会导致代收消息与审核结果推送无法路由 |
| 3 | **消息校验 Token** | 第 3 步生成的 Token | `WX_COMPONENT_VERIFY_TOKEN` | 两边不一致 → 回调验签失败 |
| 4 | **消息加解密 Key** | 第 3 步生成的 43 字符 Key | `WX_COMPONENT_ENCODING_AES_KEY` | 两边不一致 → 解密失败，回调全部报错 |
| 5 | **消息加解密方式** | **安全模式**（第三方平台只允许安全模式，选不了明文） | — | — |
| 6 | **数据格式** | **XML**（第三方平台只允许 XML，选不了 JSON） | — | — |
| 7 | （详情页）AppID | 平台 AppID | `WX_COMPONENT_APPID` | 回调 receiveid 校验失败 |
| 8 | （详情页）AppSecret | 平台 AppSecret | `WX_COMPONENT_APPSECRET` | 取令牌报 `40125` |
| 9 | （轮换时）上一版加解密 Key | 上一次的 43 字符 Key | `WX_COMPONENT_ENCODING_AES_KEY_PREV` | 换 Key 期间旧推送解不开 |

### 4.2 逐字段的「界面级」说明（文字描述）

1. **「授权事件接收配置」输入框**：位于「开发资料」页上半部分，与「消息与事件接收配置」并排。框内填第 2 步拿到的第一个 URL。它的作用是接收 `component_verify_ticket`（微信**每 10 分钟**推一次，票据有效期 **12 小时**）与 `authorized` / `updateauthorized` / `unauthorized` 授权变更通知。
2. **「消息与事件接收配置」输入框**：填第二个 URL。文本里**必须有 `$APPID$` 这 6 个字符加两个美元符号形成的占位符**，微信推送时会把它替换成授权方 appid（本平台的回调路由即 `/callback/message/:appid`）。它承载代码审核结果推送（`weapp_audit_success` / `weapp_audit_fail` / `weapp_audit_delay`）与代收消息。
3. **「消息校验 Token」输入框**：与 `WX_COMPONENT_VERIFY_TOKEN` **逐字符一致**。
4. **「消息加解密 Key」输入框**：43 字符，与 `WX_COMPONENT_ENCODING_AES_KEY` 一致。
5. **「消息加解密方式」**：第三方平台页面**只有安全模式**，不需要也无法切换。
6. **「数据格式」**：第三方平台页面**只有 XML**。
7. **「授权发起页域名」**：填与平台前端同域的域名（见第 6 步）。
8. **「授权测试公众号/小程序列表」**：未全网发布时唯一能完成授权的白名单（见第 7 步）。
9. **保存**：所有配置保存后即时生效，但**只对「授权测试公众号/小程序列表」内的账号生效；需全网发布后才对全网授权账号生效**（`docs/wx-docs/extra_config.md`）。

### 4.3 改完配置后要做的动作

```bash
# 1) 检查 .env 里 4 个值非空且长度正确
grep -E '^WX_COMPONENT_(APPID|APPSECRET|VERIFY_TOKEN|ENCODING_AES_KEY)=' server/.env
awk -F= '/ENCODING_AES_KEY=/{print "AESKey 长度:", length($2)}' server/.env   # 期望 43

# 2) 重启后端（环境变量只在启动时读取）
make dev-backend
```

| 期望看到什么 | 说明 |
|---|---|
| 启动日志**不再**出现「第三方平台凭据未配置完整」 | 说明 4 个变量齐了 |
| 概览页告警区清空或只剩票据相关提示 | 凭据已就绪 |
| 5-10 分钟后概览页「票据状态」变为正常 | 微信每 10 分钟推一次 ticket |

**检查点 4**：`server/.env` 的 4 个 `WX_COMPONENT_*` 与后台字段逐字符一致；重启后日志无「未配置」警告。

> 出问题看：第 10.3 节（回调一直收不到 ticket）。

## 第 5 步：配置 IP 白名单

| 步骤 | 在哪里点 | 填什么值 | 期望看到什么 |
|---|---|---|---|
| 5.1 | 第三方平台详情 → **开发配置 → IP 白名单** | 第 0.5 步记录的公网出口 IP（一个一行） | 列表显示已保存的 IP |
| 5.2 | 同上 | 多台机器/多出口/负载均衡/NAT 出口**全部加上** | — |

规则与坑：

- 官方原文：「上述提到的所有 API 调用需要验证调用者 IP 地址。只有在第三方平台的白名单 IP 地址列表中填写的白名单 IP 地址列表内的 IP 地址，才能合法调用，其他一律拒绝。」依据 `docs/wx-docs/token_creat_token.md`。
- 未加白名单时：**回调仍能收到 ticket**（回调是微信推给你，不校验你的 IP），但**换 `component_access_token` 会直接失败**并返回 `61004 access clientip is not registered`。这是最容易误判成「ticket 没收到」的陷阱。
- 后台该列表**只接受具体 IP，不接受网段**（如 `10.0.0.0/24` 无效），且数量有上限：常见口径是**最多 100 个**，但**本仓库的微信文档汇总与 `docs/wx-docs/` 未收录该数字，以开放平台后台页面提示为准**。
- 云函数、容器弹性伸缩、CDN 回源等场景出口 IP 会漂移，必须先把出口固定（弹性公网 IP / NAT 网关）。

**验证命令**（在服务器上执行，确认出口 IP 就是加白的那个）：

```bash
curl -s https://ifconfig.me            # 或 curl -s https://api.ipify.org
```

**检查点 5**：白名单里的 IP 与服务器实测出口 IP 完全一致（`diff` 一眼能看出差异的常见情况是：加了内网 IP、加了跳板机 IP、加了旧机房的 IP）。

> 出问题看：第 10.4 节（`61004`）。

## 第 6 步：配置权限集与授权发起页域名

### 6.1 权限集

路径：**微信开放平台 → 第三方平台 → 详情 → 开发配置 → 权限集配置**（`docs/wx-docs/extra8_how_to_service_01c.md`）。

| 勾选 | 权限集 id | 名称 | 说明 |
|---|---|---|---|
| ☑ **必勾** | **18** | 小程序开发与数据分析 | 代码上传、页面列表、提审、撤回、发布、回退、灰度、服务状态、基础库、额度查询、体验版二维码、隐私检测**全部依赖它** |
| ☐ 按需 | 30 | 小程序基本信息管理 | 设置小程序名称/头像/简介/**类目**等基本信息 |

关于权限集 18 的三个硬事实：

1. **它是「互斥权限集」**：官方原文「小程序的开发权限集授权给服务商后，为了避免代码版本互相覆盖，小程序则无法再通过公众平台进行发版本」。**这一点必须提前告知商家**，否则商家会以为你把他们的发版能力「抢走了」。
2. 互斥规则：**一个账号只能把互斥权限集授予一个服务商**；非互斥权限集一个账号最多同时授权给 15 个服务商（`docs/wx-docs/extra8_how_to_service_01c.md`）。
3. 小程序侧只有勾选了 18 才有效。已授权但缺 18 的小程序，概览页会在告警区逐条列出（「以下小程序尚未授权『小程序开发与数据分析』（权限集 18）…」）。

### 6.2 授权发起页域名

| 步骤 | 在哪里点 | 填什么值 | 期望看到什么 |
|---|---|---|---|
| 6.2.1 | 第三方平台详情 → 开发配置 → 开发资料 → **授权发起页域名** | 平台**前端**域名（例 `wx.example.com`，不带路径） | 保存成功 |
| 6.2.2 | 对照 `server/.env` | `PUBLIC_BASE_URL=https://wx.example.com` | 回调地址为 `https://wx.example.com/authorize/callback` |

**必须同域**：授权发起页域名与授权回调地址（`redirect_uri`）的域名不一致时，商家扫码后会看到「确认授权入口页所在域名，与授权后回调页所在域名相同」的报错。本平台生成授权链接时会用 `PUBLIC_BASE_URL` 推导 `redirect_uri`（`server/internal/core/authurl.go` 的 `BuildRedirectURI`），所以**只要让这两处都指向同一个域名即可**。

**检查点 6**：权限集 18 已勾选并保存；授权发起页域名 = `PUBLIC_BASE_URL` 的域名；`GET /platform/status` 返回的 `authRedirectUri` 与该域名同域。

> 出问题看：第 10.2 节（商家扫码报错）。

## 第 8 步：绑定开发小程序【人工，无 API】

**本平台不提供、也不可能提供**这一步：微信没有对应 API，只能在开放平台后台点。

| 步骤 | 在哪里点 | 填什么值 | 期望看到什么 |
|---|---|---|---|
| 8.1 | **微信公众平台**注册一个普通小程序，完善**头像、昵称、简介、服务类目** | — | 小程序资料完整 |
| 8.2 | **微信开放平台 → 第三方平台详情 → 绑定开发小程序** | 选 8.1 的小程序 | 列表中出现该小程序 |
| 8.3 | 微信开发者工具，用**开发小程序的开发者微信号**登录 | — | 可以正常上传 |
| 8.4 | 开发者工具点「上传」 | 填版本号、描述 | 代码进入**开放平台草稿箱**（不是公众平台） |
| 8.5 | 平台 **代码模板** 页 → 「同步草稿箱」 | — | 草稿列表出现刚才上传的记录 |

关键事实（`docs/wx-docs/extra_how_to_dev.md`）：

- 绑定为开发小程序后，**该小程序在开发者工具中上传的代码会直接上传到开放平台，不会上传到公众平台**。
- 从开发者工具上传的代码先在**草稿箱**，**每个开发小程序只保留最新一份上传记录**；添加到**模板库**后**不会被覆盖**，可获得 `template_id`。
- 上传也可以走 `miniprogram-ci`（`directCommit` 同样适用于 CI）。

数量上限：本平台与本地微信文档汇总**均未收录**「最多绑定 30 个」这类数字，请以后台页面提示为准。

【本平台不做】不要把它和权限集 25 的「开放平台账号管理」（`bindOpenAccount`，绑定/解绑开放平台账号）搞混：那是另一件事，本平台不调用该接口。

**检查点 8**：平台「代码模板」页能同步出草稿，并成功「添加到模板库」拿到 `template_id`。

> 出问题看：第 10.5 节（提审报 `85008`/无类目）、`README.md` 6.2 节。

## 第 9 步：全网发布

路径：**第三方平台详情 → 开发信息 → 开发资料 → 全网发布**（`docs/wx-docs/extra5_publish_ac2.md`）。

| 步骤 | 在哪里点 | 期望看到什么 |
|---|---|---|
| 9.1 | 全网发布入口 | 进入后可见「全网发布接入检测」 |
| 9.2 | 点开始检测 | 逐项显示检测结果 |
| 9.3 | 若有项不通过 | 按下面的自检清单修正后重新检测 |
| 9.4 | 全部通过 | 确认发布，之后可服务任意符合要求的小程序 |

### 9.1 检测自检清单（逐条核对）

- [ ] **9.1.1 授权事件接收 URL 可达**：从公网能 POST 到 `{PUBLIC_BASE_URL}/callback/component`（可临时用 `curl -i -X POST {URL}` 确认返回的是 `success` 或 400 而不是连不上/502）。
- [ ] **9.1.2 对 `component_verify_ticket` 只返回纯文本 `success`**：这是官方硬性要求——「接收 POST 请求后，只需直接返回字符串 `success`」（`docs/reference/wx-open-platform-api.md` 1.2）。**不要返回 JSON、不要加密、不要带引号或换行**。本平台的回调实现在校验 `msg_signature`、登记事件后返回该字符串。
- [ ] **9.1.3 消息与事件接收 URL 可达且带 `$APPID$`**：后台里必须是 `{PUBLIC_BASE_URL}/callback/message/$APPID$`。
- [ ] **9.1.4 Token / EncodingAESKey 与 `.env` 一致**：Token、Key 任一处不一致都会验签或解密失败。
- [ ] **9.1.5 处理专用测试消息**：检测会向消息与事件接收 URL 推送专用测试消息（客服消息 `TESTCOMPONENT_MSG_TYPE_TEXT` 与 `QUERY_AUTH_CODE:$code$` 两类）。**本仓库的微信文档汇总与 `docs/wx-docs/` 未收录《全网发布接入检测说明》原文**，请在做全网发布前打开官方页面核对当期要求；本平台对这些推送的处置是「登记到『日志 → 回调事件』并按通用规则返回 `success`」。
- [ ] **9.1.6 回调验签只用 `msg_signature`**：官方明确警告「不要使用 `signature` 验证」。本平台已按要求实现；如果你改了回调代码，别改这一条。
- [ ] **9.1.7 receiveid 分流校验**：授权事件 URL 用**第三方平台 appid**，代收消息用**授权方 appid**（`AGENTS.md` 第 3 条）。校验失败会被记为签名/解密失败，不会误判为「微信没推」。
- [ ] **9.1.8 IP 白名单已完成**（第 5 步）：检测过程中会实际调用接口，白名单没配会以 `61004` 失败。

### 9.2 票据收不到时的恢复手段

官方提供 `api_start_push_ticket`（`POST /cgi-bin/component/api_start_push_ticket`，请求体 `{"component_appid":"...","component_secret":"..."}`，返回 `{errcode, errmsg}`，`0` 含义为「ok（从不正常变正常）或 in a normal state（本来就正常）」；依据 `docs/wx-docs/token_startpushticket.md`）。

【注意】**本平台当前未把该操作暴露成界面或接口**（`server/internal/wxtoken` 内有 `EnsurePushTicket` 能力，但 `api/openapi.yaml` 中没有对应端点）。需要时按 `docs/runbook.md` 第 1 节的命令直接调用。

**检查点 9**：全网发布已完成，或（若暂不发布）已明确记录「当前仅测试号可用，禁止对生产小程序发作业」。

## 第 10 步：常见接入失败定位

每条都给出「现象 → 判断 → 处置 → 看哪一节」。

### 10.1 授权链接打不开

| 阶段 | 现象 | 判断 | 处置 |
|---|---|---|---|
| 现象 | 点「生成授权链接」报 409/502，或复制出来的链接在浏览器里报错 | — | 先看**日志 → 微信调用日志**过滤 `endpoint=/cgi-bin/component/api_create_preauthcode` |
| 判断 A | 接口返回 `61004` | IP 白名单未配 | 做第 5 步 |
| 判断 B | 接口返回 `40001`/`42001` | 令牌失效 | `docs/runbook.md` 第 2 节 |
| 判断 C | 报错含「第三方平台凭据未配置」 | `.env` 的 4 个 `WX_COMPONENT_*` 不全 | 回到第 4 步 |
| 判断 D | 链接能生成，但打开是「页面不存在」 | `redirect_uri` 为空或域名未备案/不可达 | 确认 `PUBLIC_BASE_URL` 已配、域名可公网访问、`authRedirectUri` 正确 |
| 判断 E | 生成时报「预授权码为空」 | 预授权码未取到 | 看接口日志的 errcode（`61004` / `40125` 最常见） |

**验证**：重新生成链接，`pcUrl` 能在浏览器打开并出现二维码；链接里的 `component_appid` 与 `WX_COMPONENT_APPID` 一致。

### 10.2 商家扫码报错

| 商家看到的报错 | 原因 | 谁来做 | 处置 |
|---|---|---|---|
| 「该公众号/小程序未授权给该第三方平台」 / 授权页直接拒绝 | 小程序**不在「授权测试公众号/小程序列表」**内，且平台未全网发布 | 你 | 做第 7 步，或先完成第 9 步全网发布 |
| 「确认授权入口页所在域名，与授权后回调页所在域名相同」 | 授权发起页域名与 `redirect_uri` 域名不一致 | 你 | 做第 6.2 步 |
| 扫出来只有该 appid 的管理员才能授权 / 其他人扫报错 | 链接带了 `biz_appid`，**它优先级高于 `auth_type`** | 你 | 确认是否需要指定单号：不需要就去掉 `biz_appid` 重新生成 |
| 授权页里**看不到「小程序开发与数据分析」**可勾 | 权限集未配置或未保存；或平台未全网发布时该权限集未生效 | 你 | 做第 6.1 步，并确认权限集配置已保存 |
| 授权成功但小程序列表里没有 | 回调页没走完（浏览器关了），`authorized` 事件还没到 | — | 等 1-2 分钟后点**同步全部**，或看「日志 → 回调事件」是否有 `authorized` |
| 授权后仍提示「缺 18」 | 商家授权时没勾权限集 18 | 商家 | 让商家重新扫码授权并**单独勾选** 18 |

**验证**：授权后「小程序管理」列表出现该小程序、`authorizationStatus=authorized`、权限集一栏含 18；「日志 → 回调事件」有 `kind=component`、`infoType=authorized` 的记录且 `signatureOk=true`。

### 10.3 回调一直收不到 ticket

按顺序排查，**每一步都要有明确结论再往下走**：

| # | 检查 | 命令 / 界面 | 结论 |
|---|---|---|---|
| 1 | 后台填的授权事件 URL 是否等于平台推导的 URL | 概览 → 接入配置卡片，或 `GET /platform/status` 的 `authorizationEventUrl` | 不一致就改成后台的值 |
| 2 | URL 是否公网可达 | `curl -i -X POST {URL}` | 连不上 → 查 DNS/证书/防火墙/反向代理/安全组 |
| 3 | 平台是否收到了请求 | 界面：**日志 → 回调事件**，`kind=component` | **没有记录** → 微信没推到（回第 1/2 步）；**有记录但 `signatureOk=false`** → Token/Key 不一致（第 4 步） |
| 4 | 票据是否真的到了 | 概览页「票据状态」；`GET /platform/status` 的 `ticketFresh` / `ticketAgeSeconds` / `ticketUpdatedAt` | `ticketFresh=false` → 走 `docs/runbook.md` 第 1 节 |
| 5 | 防火墙/安全组/反代是否只放行了 GET | 反代配置 | 回调是 **POST + XML**，只放行 GET 会 405 |
| 6 | IP 白名单是否配好 | 第 5 步 | 未配 → 回调能收到但取令牌报 `61004`（第 10.4 节） |

详细处置（含 `api_start_push_ticket` 与 12 小时票据兜底）见 `docs/runbook.md` 第 1 节。

### 10.4 `61004` 调用来源 IP 未注册

| 阶段 | 内容 |
|---|---|
| 现象 | 任意微信接口失败，`errcode=61004`，`errmsg=access clientip is not registered` |
| 判断 | 服务器**公网出口 IP** 不在第三方平台 IP 白名单；注意回调能正常收 ticket 并不代表白名单配好了 |
| 处置 | 1) 服务器上 `curl -s https://ifconfig.me` 取真实出口 IP；2) 第三方平台详情 → 开发配置 → **IP 白名单** 加入该 IP；3) 多出口/多机器全部加入；4) 重启后端不必，直接重试接口 |
| 验证 | 「日志 → 微信调用日志」按 `errcode=61004` 过滤，重新触发一次调用后应出现 `ok=true` 的记录 |
| 注意 | 只支持**具体 IP、不支持网段**；上限数量见后台页面提示（本地文档未收录）；本平台把这些码归入 `environment` 类，**不消耗重试次数** |

### 10.5 `61007` 权限集未授权

| 阶段 | 内容 |
|---|---|
| 现象 | 代码管理类接口失败，`errcode=61007`，`errmsg=api is unauthorized to component` |
| 判断 | 小程序**没有把对应权限集授予本第三方平台**（代码管理需要 18）。这是「没授权」，与 `48001`「账号自身没有该接口权限」是两回事 |
| 处置 | 让**商家**重新扫码授权并勾选权限集 18；平台不重试（`permanent`） |
| 验证 | 「小程序管理」详情里权限集含 18；重跑体检，`dev_permission` 检查项为 `pass` |
| 相关 | `48001`（api 功能未授权）是**小程序自身**没开通该接口权限，由商家在小程序侧处理，平台无法代改；`61014` 是**用错令牌**（该用 component 却用了 authorizer） |

### 10.6 其它高频接入错误

| errcode | 现象 | 处置 |
|---|---|---|
| `40125` | 取令牌失败，`invalid appsecret` | 核对 `WX_COMPONENT_APPSECRET`；刚重置过 AppSecret 就必须更新 `.env` 并重启 |
| `61005` / `61006` | ticket 过期/无效 | 用 12 小时内最近可用的票据；长时间无效走 runbook 第 1 节 |
| `61028` | 第三方平台未发布 | 完成第 9 步全网发布 |
| `85008` | 提审报「当前小程序没有已审核通过的类目」 | 在**小程序侧**添加类目并等审核通过；类目字段取自 `getAllCategoryName` |
| `85065` | 模板库已满 | 模板库上限 200，先删除不用的模板 |
| `9402203` | 标准模板 `ext_json` 错误 | 标准模板官方已下架，改用普通模板（`template_type=0`） |

## 附录 A：一次性验收（接入完成的判定）

- [ ] 概览页「票据状态」显示正常（票据在 20 分钟内收到），「平台令牌」显示有效。
- [ ] 概览页告警区没有「凭据未配置 / 票据缺失 / 缺权限集 18 / 模板库已满 / 额度用尽」类提示。
- [ ] `GET /platform/status` 的 `authorizationEventUrl`、`messageEventUrl` 与开放平台后台逐字符一致。
- [ ] 测试小程序完成一次**真实授权**，列表里能看到它并且权限集含 18。
- [ ] 「代码模板」页能同步草稿并加入模板库，拿到 `template_id`。
- [ ] 「前置体检」对该小程序给出 `ready=true`。
- [ ] 「日志 → 回调事件」能看到 `component_verify_ticket` 与 `authorized` 记录；「日志 → 微信调用日志」能看到 `ok=true` 的调用记录。
- [ ] 找一个失败调用按 `errcode` 过滤，能定位到具体 `endpoint` 与 `appid`。
